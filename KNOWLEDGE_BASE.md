## 2. Командная архитектура (Team Roles)
Для высокого качества кода и дизайна используется ролевая модель 5 специалистов:
1. **Главный архитектор**: Проектирует структуру файлов и логику потоков данных.
2. **Критик-контроллер**: Проверяет код на избыточность, безопасность и соответствие стандартам React/Vite.
3. **Руководитель проекта (РП)**: Гарантирует целостность продукта и соответствие запросу пользователя.
4. **Тестировщик**: Эмулирует поведение пользователя на iOS/Android, проверяет граничные случаи PWA.
5. **Дизайнер-визионер**: Создает «атмосферу» через шрифты, текстуры и микро-анимации.

## 3. PWA Механики (Advanced PWA Logic)
*Самая сложная и удачная часть приложения, обеспечивающая нативный опыт в браузере.*

### Механика 3.1: Глобальный перехват Install Prompt
- **Решение**: В `index.html` реализован `EventListener` для `beforeinstallprompt`, который сохраняет событие в `window.deferredPrompt` еще ДО загрузки React.
- **Профит**: Мы не теряем возможность установки, если пользователь зашел на страницу и React еще не успел смонтировать компоненты.

### Механика 3.2: Координация Popup-окон (Priority System)
- **Проблема**: Конфликт окна «Установить» и «Доступно обновление».
- **Решение**: Использование глобального флага `window.pwaPopupActive` и кастомного события `pwa-popup-closed`. 
- **Приоритеты**:
  1. Окно обновления (Критично).
  2. Окно установки (Показывается только если нет обновлений и флаг активности пуст).

### Механика 3.3: Кроссплатформенные инструкции
- **Android**: Автоматический вызов системного диалога `prompt()` через кнопку в интерфейсе.
- **iOS**: Визуальная инструкция (анимированные подсказки: «Поделиться» -> «На экран "Домой"»), так как iOS не поддерживает стандартный API установки.
- **FAB (Floating Action Button)**: Постоянная кнопка установки, которая появляется в углу экрана, если приложение еще не установлено.

### Механика 3.4: Приветствие Standalone (Beatitudes)
- **Механика**: В `Home.tsx` реализовано автовызов окна «Заповедей Блаженств» ПРИ ПЕРВОМ входе именно в установленное приложение (standalone mode). Это создает ощущение «награды» за установку.

## 4. Дизайн-система «Монашеский минимализм»
*Рецепт создания глубокого погружения в атмосферу приложения.*

### 4.1. Визуальный код
- **Шрифт**: `Izhitsa` (Ижица) — для заголовков (символ традиции). `Serif` — для длинных чтений (удобочитаемость).
- **Цветовая палитра**: 
  - `Cinnabar` (#C33B3B) — акценты, киноварь.
  - `Parchment` (#FCFAF7) — фон, эффект старой бумаги.
  - `Ink` (#1A1A1A) — текст.
- **Декоративный элемент (`DecorativeDivider`)**: Адаптивный разделитель с градиентом от прозрачного к `Cinnabar` и символом `❦` в центре.

### 4.2. UX Паттерны
- **Smooth Layout**: Использование `motion/react` для плавных переходов между страницами (fade-in, slide-up).
- **BackToTop**: Умная кнопка «Наверх», появляющаяся при скролле более 300px, привязанная к контейнеру `main`.
- **Safe Area Insets**: Использование `env(safe-area-inset-bottom)` в CSS для корректного отображения на iPhone с "челками".

## 5. Технический Стек и Хранение
- **Persistence (Zustand)**: Использование `persist` middleware для хранения Дневника Исповеди в `localStorage`. Данные пользователя не уходят на сервер.
- **Asset Strategy**: Хранение книг в `.epub` и `.fb2` в `/public/books/` с механизмом прямого скачивания через скрытую ссылку (`fileDownloader.ts`).
- **HashRouter**: Использование хеш-навигации для бесконфликтной работы на статическом хостинге и внутри PWA без настройки серверных редиректов.

## 7. Защита активов от деградации (Asset Security)
*Механика сохранения качества медиа-файлов при экспорте и работе с Git.*

- **Файл**: `.gitattributes`.
- **Суть**: Принудительное назначение флага `binary` для всех типов изображений, шрифтов и документов. 
- **Зачем**: Предотвращает «битые пиксели» и повреждение структуры файлов (шрифтов, epub) из-за автоматической смены кодировок строк в системах контроля версий.
- **Список расширений**: `.webp`, `.png`, `.jpg`, `.svg`, `.ttf`, `.woff`, `.epub`, `.fb2`.

## 8. Механика закладок (Reading Progress)
*Позволяет пользователю сохранять место чтения в больших текстовых разделах.*

- **Хранилище**: `p_bookmarks` в `localStorage` (через `useBookmarksStore`).
- **Логика работы**:
  1. На каждой секции текста (например, в Евангельских заповедях) добавлена кнопка-иконка `Bookmark`.
  2. При клике ID элемента сохраняется в глобальный стейт по ключу страницы.
  3. При повторном входе на страницу появляется кнопка «Продолжить чтение», которая плавно прокручивает страницу к сохраненному ID.
- **UI/UX**: 
  - Иконки `lucide-react` (`Bookmark` / `BookMarked`).
  - Визуальное выделение (ring/shadow) текущей заложенной секции.
  - Анимированная кнопка продолжения чтения с задержкой появления (`setTimeout`) для привлечения внимания.

## 9. Проактивное обнаружение обновлений (Active SW Polling)
*Гарантирует, что пользователь увидит уведомление об обновлении даже в установленном PWA.*

- **Механика 9.1: Поллинг (Polling)**: 
  - Использование `onRegistered` в `useRegisterSW` для запуска `setInterval`, который вызывает `r.update()` каждый час.
- **Механика 9.2: Visibility Check**:
  - Слушатель события `visibilitychange`. Когда приложение выходит из фона (пользователь открыл его снова), вызывается принудительная проверка обновлений.
- **Механика 9.3: Версионный хук**:
  - Сравнение `CURRENT_VERSION` (в коде) с сохраненным значением в `localStorage`. Это позволяет показать попап «Приложение обновилось!» даже если Service Worker обновился незаметно для пользователя.
